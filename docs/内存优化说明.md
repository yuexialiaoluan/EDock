# EDock 0.16.3 隐藏待机内存优化

本版继续针对“两侧边栏隐藏、设置窗口关闭时，尽量降低待机占用”的需求，减少隐藏期间持续产生的临时对象。

**0.16.2 测到的约 5–7 MiB 是短时间样本，不是长期待机保证。** 一次回收后，触边检测、快捷模式和界面框架仍会运行，相关页面会逐渐回到物理内存；临时对象的累积和回收也会使数字变化。一直隐藏时，占用仍可能从最初低点回升。

## 为什么隐藏后仍缓慢增长

本轮对旧正式版本的隐藏状态观察中，程序仍平均每秒申请约 25 KB 临时对象（约 25,202 字节/秒）。一次自动垃圾回收后，托管堆从约 19 MB 降到约 3 MB，说明这部分增长中有大量可以回收的临时对象，不能直接认定为一直保留、无法释放的泄漏。

此前快捷模式开启后，即使尚未进入快捷模式，也每 16 毫秒执行一次备用状态校正。窗口类名读取、按键状态筛选及计时器属性访问会反复创建临时对象；再加上框架页面重新调入，导致任务管理器中的数字逐渐回升。仅清空一次工作集，无法消除这些后续活动。

## 0.16.3 改了什么

- 读取前台窗口类名时直接使用临时栈缓冲，避免重复创建文本对象。
- 复用按键筛选逻辑，减少快捷模式轮询中的临时对象。
- 缓存计时器的当前间隔，只有状态改变时才更新，避免每次轮询反复访问界面框架属性。
- 快捷模式开启但尚未使用时，备用校正改为每 100 毫秒一次；进入快捷模式、开始 Ctrl 候选手势或有待处理操作时，保持每 16 毫秒一次。

正常 Ctrl、W / S、空格和滚轮仍由输入监听即时处理，无需等待上述计时器。取舍是：非活动状态下，如果系统偶尔漏掉一次按键释放事件，备用校正可能需要等待最多 100 毫秒。已开始的 Ctrl 候选手势和活动中的快捷模式仍使用 16 毫秒校正。

这轮修改针对明确找到的持续分配来源，不代表已排除所有内存泄漏，也不承诺待机数字恒定不变。

## 0.16.3 八分钟对照

在同一台电脑上，0.16.2 和 0.16.3 同时运行各自的隔离配置；两侧边栏始终隐藏、设置窗口始终关闭，快捷模式保持开启。采样只读取进程指标，不执行强制回收、工作集清理或内存上限控制。

| 指标 | 0.16.2 | 0.16.3 |
| --- | ---: | ---: |
| 8 分钟开始私有工作集 | 4.75 MiB | 4.59 MiB |
| 8 分钟结束私有工作集 | 18.15 MiB | 8.48 MiB |
| 私有工作集变化 | +13.40 MiB | +3.89 MiB |
| 私有提交量变化 | +9.17 MiB | -0.66 MiB |

两次采样均确认两侧隐藏、设置关闭。0.16.3 在第 3 分钟到结束只增加约 0.66 MiB 私有工作集，私有提交量基本稳定；这说明持续增长已明显减缓，但不能据此承诺无限长时间绝对不增长。

## 继续保留的隐藏回收

- 每侧隐藏 8 秒后，释放该侧的图标控件、图像缓存和背景材质；同一列表保留滚动位置。
- 两侧都完成释放、设置关闭且没有交互后，再等待 3 秒，将暂时不用的驻留页面交给 Windows 按需复用。通常在最后一侧隐藏约 11 秒后执行。
- 每次进入待机只执行一次。显示边栏、打开设置或使用托盘菜单会取消等待；固定展开、快捷模式、拖动、排序等操作期间暂停回收。
- 保留触边检测、托盘及快捷模式响应，没有增加常驻进程、周期性工作集清理、内存上限或强制 GC。

## 0.16.2 历史短时实测

以下保留此前的测试记录，**不是 0.16.3 的对照结果，也不能代表长期待机占用**。本机 Windows 11 x64，0.16.1 与 0.16.2 使用同一份 14 项快捷方式配置，分别运行独立测试实例。依次测量启动隐藏、左右各显示后隐藏、开关设置后隐藏，以及再两轮左右显示后隐藏。每个隐藏阶段连续采样 60 秒，下表取最后 5 秒均值，单位 MiB。

“私有工作集”是当前驻留物理内存中该进程独有的部分，不含共享框架页面；它与“私有提交量”是两个指标。

| 隐藏待机阶段 | 0.16.1 私有工作集 | 0.16.2 私有工作集 | 0.16.1 私有提交量 | 0.16.2 私有提交量 |
| --- | ---: | ---: | ---: | ---: |
| 启动后 | 52.2 | 7.2 | 115.6 | 116.1 |
| 首轮左右显示后 | 60.4 | 5.3 | 123.8 | 123.8 |
| 打开并关闭设置后 | 70.7 | 4.9 | 135.0 | 135.7 |
| 再次左右显示后 | 69.5 | 7.2 | 133.1 | 137.0 |
| 第三轮左右显示后 | 69.8 | 6.8 | 133.8 | 137.7 |

这组短时样本中，0.16.2 待机私有工作集约 5–7 MiB，减少约 86–93%；包含共享页面的总工作集约 9–18 MiB。私有提交量没有下降。每个阶段均确认两栏原生窗口隐藏、设置窗口不存在；测量期间不查询隐藏边栏的界面控件，测试脚本本身不执行内存清理。

当时的 0.16.2 正式运行实例另做了 40 秒连续观察，全程确认两侧隐藏、设置关闭。最后 5 秒均值：私有工作集 10.4 MiB，包含共享页面的总工作集 21.0 MiB，私有提交量 138.4 MiB。此项使用用户当时实际运行环境，区别于上面的独立对照实例；数值会随系统缓存和此前操作变化。当时原有设置、列表及快捷方式文件的最终保留核验通过。

首次隐藏 60 秒后，旧版左右边栏完整滑入屏幕分别约 411 / 432 毫秒，新版约 437 / 448 毫秒，均包含原有显示延迟及滑入动画。此时间反映窗口几何完成，不等于所有图像已加载；图标、图片、材质及滚动位置另做恢复检查。

待机 CPU 在两版测试中都处于很低水平；本次回收没有新增周期轮询。上述数据是本机样本，不代表固定上限，会随系统缓存、图片、列表数量和操作变化。

## 取舍与限制

这是降低隐藏时的物理驻留占用。程序申请的提交内存仍然保留，也没有卸载 WinUI / .NET 框架；不能将工作集下降理解成消除了等量内存分配或修复了所有内存增长。

移出的页面可能暂存在系统内存缓存中，Windows 可以按需复用，因此系统总内存不一定立即等量下降。再次显示或打开设置时需调回相关页面，内存紧张、需要从磁盘读取时可能明显变慢；显示期间占用回升属于正常现象，再次进入待机后会重新回收。

即使隐藏状态完全不变，框架运行和系统消息也可能使工作集回升。判断是否泄漏，需要同时看更长时间的提交内存、回收后的存活对象和资源数量，不能只看回收后的最低数字。

图片清晰度、背景材质和现有交互保留。设置页面延迟创建主要影响打开设置的峰值，本次未做这一改造。
